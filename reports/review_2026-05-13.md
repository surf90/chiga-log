## 観点1: 総合コードレビュー・監査

### 🔴 1-1. Stormglassフォールバック時のデータ形式が app.js と非互換 (Critical)

**場所**: [scripts/extract_daily_data.py:151-160](scripts/extract_daily_data.py:151)

```python
forecast.setdefault(ds, []).append({
    "time": dt_jst.strftime("%H:%M"),          # ← "HH:MM" のみ。ISO形式ではない
    "height": item.get("height"),
    "type": "H" if item.get("type") == "high" else "L",  # ← "H"/"L" → app.js は "high"/"low" を期待
})
```

**問題**: [assets/js/app.js:217-224](assets/js/app.js:217) では `new Date(item.time)` でパースし、`item.type === 'high'` で分岐する。Stormglass経路では:
1. `"HH:MM"` 単体は `new Date()` で **Invalid Date** → グラフ崩壊
2. `type === 'H'` は `'high'` と一致せず、すべて干潮側に分類

**影響**: 気象庁データ取得失敗時の救済策が機能せず、ユーザーには「取得失敗」UIではなく**誤った潮汐情報**が表示される（三原則1「ダミー値で誤読を誘発しない」に違反）。

**修正案**:
```python
forecast.setdefault(ds, []).append({
    "time": dt_jst.isoformat(timespec="seconds"),
    "height": item.get("height"),
    "type": "high" if item.get("type") == "high" else "low",
})
```

### 🔴 1-2. `let _isFetching` ほかが使用箇所より後ろで宣言 (Critical 寄り High)

**場所**: [assets/js/app.js:848-949](assets/js/app.js:848)

`fetchWeatherData()` が `_isFetching` / `_lastFetchTime` を参照（848, 934行）するが、これらは [949-951行](assets/js/app.js:949) で `let` 宣言。実行時はDOMContentLoadedで関数呼び出しが行われるため動作しているが、`let` のTDZ仕様上、ファイル先頭から **静的解析ツールが警告**を出すレベル。将来モジュール化した際にReferenceErrorで壊れる。

**修正案**: 関連3変数（`_isFetching`, `_toastShown`, `_lastFetchTime`）を `fetchWeatherData` 定義の**前**へ移動。

### 🟠 3-4. `fetchJmaForecast` の TS仕様前提

[assets/js/app.js:551-568](assets/js/app.js:551) で `timeDefines` が `[今日09, 今日00, 明日00, 明日09]` 順であることを前提に最高/最低気温を抽出。JMAが配列順を変えれば壊れる。

### 🟠 3-5. `fetchWindForecast` の date 比較がローカルTZ依存

[assets/js/app.js:631-643](assets/js/app.js:631)

```js
const today = now.toDateString();
...
.filter(item => ... && item.date === today)
```

`toDateString()` は実行環境のローカルTZに依存。Open-Meteoは `&timezone=Asia/Tokyo` で取得済みのため通常はJST一致するが、**ブラウザがJST以外のユーザー**（海外旅行先からアクセス等）では `today` がズレ、当日分が0件になる。

**修正案**: `today` を「JST基準の日付文字列」に固定:
```js
const today = new Date(now.getTime() + 9*3600*1000).toISOString().slice(0,10);
const itemDateJst = new Date(dt.getTime() + 9*3600*1000).toISOString().slice(0,10);
// item.date === today の比較を上記JST文字列同士に変更
```

### 🟡 4-2. `fetchWithCache` / `fetchWithLocalCache` の統合

[assets/js/app.js:22-51](assets/js/app.js:22) はほぼ同一。

```js
async function fetchCached(url, key, { store = 'session', ttlMs = 30*60*1000 } = {}) {
    const storage = store === 'local' ? localStorage : sessionStorage;
    const cached = storage.getItem(key);
    if (cached) {
        try {
            const { data, ts } = JSON.parse(cached);
            if (Date.now() - ts < ttlMs) return data;
        } catch { storage.removeItem(key); }
    }
    const res = await fetch(url);
    if (!res.ok) throw new Error(`fetch failed: ${url}`);
    const data = await res.json();
    storage.setItem(key, JSON.stringify({ data, ts: Date.now() }));
    return data;
}
```

呼び出し側: `fetchCached(url, key)` / `fetchCached(url, key, { store: 'local', ttlMs: 10*60*1000 })`。
